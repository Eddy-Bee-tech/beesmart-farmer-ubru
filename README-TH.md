# BeeSmart Farmer Web Prototype 1.0

รุ่นทดลองแบบเว็บ/PWA แยกจากโครงการ Native React Native เดิม

## ความสามารถในรุ่นทดลอง
- โปรไฟล์เจ้าของฟาร์ม
- จัดการฟาร์ม จุดเลี้ยง และรังผึ้ง
- บันทึกตรวจรัง ให้อาหาร และเก็บเกี่ยว
- บัญชีรายรับ/รายจ่าย
- Dashboard สรุปจำนวนและยอดเงิน
- เก็บข้อมูลใน IndexedDB บนอุปกรณ์ และเปิดออฟไลน์หลังโหลดครั้งแรก
- ส่งออก/นำเข้าข้อมูลสำรอง JSON
- รองรับติดตั้งเป็นไอคอน PWA บนหน้าจอหลัก iPhone เมื่อเผยแพร่ผ่าน HTTPS

## ข้อจำกัด
นี่เป็นเว็บต้นแบบแยกต่างหาก ไม่แก้ไขโครงการ React Native เดิม และยังไม่ใช่ native iOS app. รุ่นนี้ยังไม่มี QR camera, encrypted backup, PDF/XLSX, direct device transfer, biometric lock หรือ multi-device sync. JSON backup ยังไม่เข้ารหัส โปรดเก็บไฟล์อย่างปลอดภัย.

## ทดสอบบนคอมพิวเตอร์
ต้องเปิดผ่าน localhost หรือ HTTPS (ไม่ใช่ดับเบิลคลิก index.html):

```bash
python -m http.server 8080
```
แล้วเปิด http://localhost:8080

## ติดตั้งบน iPhone
1. เผยแพร่โฟลเดอร์นี้บน static hosting ที่รองรับ HTTPS เช่น GitHub Pages หรือ Netlify (ไฟล์แอปเป็น static; ข้อมูลฟาร์มยังอยู่ในเครื่อง ไม่ส่งขึ้น hosting)
2. เปิด URL ผ่าน Safari บน iPhone
3. กด Share > Add to Home Screen > Add
4. เปิดจากไอคอน BeeSmart Farmer และทดสอบเพิ่มข้อมูล จากนั้นเปิด Airplane Mode เพื่อทดสอบออฟไลน์

หมายเหตุ: PWA ต้องโหลดครั้งแรกขณะออนไลน์เพื่อ cache ไฟล์แอป; iOS อาจมีข้อจำกัดการจัดเก็บข้อมูลของเว็บแอปและผู้ใช้ควรส่งออก backup เป็นระยะ.

## รายการปรับปรุงในชุดแก้ไข
- เพิ่มไอคอน PNG 192/512 ที่อ้างถึงใน manifest และ Service Worker
- เปลี่ยนชื่อ cache เป็น v2 เพื่อบังคับติดตั้ง cache ชุดใหม่
- ตรวจรหัสรังไม่ซ้ำกันทั้งฟาร์ม (ไม่ใช่เฉพาะจุดเลี้ยงเดียว)
- แสดงรหัสรังพร้อมจุดเลี้ยงและฟาร์มในช่องเลือกกิจกรรม
- ตรวจสอบข้อมูลสำรองก่อนนำเข้าและบันทึกเป็น transaction เดียว
- หน่วงเวลายกเลิก object URL หลังส่งออกเพื่อเพิ่มความเสถียรในการดาวน์โหลด

หมายเหตุ: การแก้ไขนี้เป็นการตรวจและปรับโค้ด ไม่ใช่ผลการทดสอบบน iPhone จริง ต้องทดสอบผ่าน HTTPS/Safari ก่อนใช้งานจริง


## ปรับปรุงระบบจัดการรัง (รุ่นแก้ไข)
- แนะนำรหัสรังอัตโนมัติ B001, B002, B003 แยกตามจุดเลี้ยง
- ตรวจรหัสซ้ำภายในจุดเลี้ยงเดียวกันด้วย IndexedDB read-write transaction
- เมื่อพบรหัสซ้ำ แจ้งเตือนพร้อมแนะนำรหัสถัดไป
- เพิ่มปุ่มแก้ไขและลบรัง
- หากรังมีประวัติกิจกรรม จะเก็บรังเข้าคลังแทนการลบจริง เพื่อรักษาประวัติ
- ป้องกันการส่งฟอร์มซ้ำด้วยการล็อกปุ่มบันทึกระหว่างดำเนินการ


## รุ่น 1.2 – แก้ไขการแนะนำรหัสรัง
- เมื่อเปิดแบบฟอร์มเพิ่มรัง ระบบคำนวณรหัสใหม่จากจุดเลี้ยงที่เลือกทุกครั้ง ไม่ใช้ค่าค้างจากแบบฟอร์มก่อนหน้า
- เมื่อเปลี่ยนจุดเลี้ยง ระบบคำนวณรหัสแนะนำใหม่ทันที
- ปิด autocomplete ของช่องรหัสรังเพื่อลดโอกาสที่เบราว์เซอร์เติมค่ารหัสเก่า


## รุ่น 1.3 – ป้องกันกิจกรรมซ้ำและจัดการประวัติ
- ป้องกันการส่งฟอร์มซ้ำด้วยการล็อกปุ่มบันทึกระหว่างทำงาน (ใช้กลไกเดิมของ modal)
- ตรวจจับรายการกิจกรรมที่เหมือนกันทุกช่องหลัก ได้แก่ ประเภทกิจกรรม รัง วันที่ รายละเอียด ปริมาณ หน่วย และหมายเหตุ
- หากพบรายการเหมือนกัน ระบบแจ้งเตือนและให้ผู้ใช้ยืนยันก่อนบันทึกซ้ำ เพื่อไม่ปิดกั้นกรณีทำกิจกรรมจริงซ้ำในวันเดียวกัน
- เพิ่มปุ่มแก้ไขและลบในประวัติตรวจรัง ให้อาหาร และเก็บเกี่ยว
- การแก้ไขคงรหัสรายการเดิม การลบกระทบเฉพาะรายการที่เลือก และมีหน้าต่างยืนยันก่อนลบ
- ปรับ Service Worker cache เป็น v4 เพื่อให้โหลดไฟล์ JavaScript รุ่นใหม่

ข้อควรทราบ: ระบบตรวจจับความซ้ำเป็นการเตือนแบบ exact-match ไม่ได้ห้ามกิจกรรมซ้ำโดยเด็ดขาด ผู้ใช้สามารถยืนยันบันทึกซ้ำได้เมื่อเป็นกิจกรรมจริงคนละรอบ


## รุ่น 1.4 – ตรวจสอบข้อมูลซ้ำและปรับปรุง Offline Cache
- แจ้งเตือนรหัสรังซ้ำที่มีอยู่ใน IndexedDB เดิม โดยไม่ลบหรือรวมข้อมูลอัตโนมัติ
- แสดงป้ายรหัสซ้ำและปุ่มแก้ไข/ลบให้เห็นชัดเจนในบัตรรัง
- ปรับการจัดการข้อผิดพลาดของการบันทึกรังให้ไม่ค้างเมื่อพบรหัสซ้ำ
- ปรับ Service Worker เป็น cache v5 และตรวจไฟล์ HTML/JS/CSS ใหม่ก่อนใช้ cache เพื่อให้รับรุ่นใหม่ได้
- กิจกรรมซ้ำยังต้องยืนยันอย่างชัดเจนก่อนบันทึกเป็นอีกรอบ


## รุ่น 1.5 – สร้างรหัสรังเมื่อเว้นว่างและปรับการตรวจรายการซ้ำ
- อนุญาตให้เว้นช่องรหัสรัง ระบบสร้างรหัสถัดไปให้ในจุดเลี้ยงที่เลือกขณะบันทึกจริง
- คำนวณรหัสจากข้อมูล IndexedDB ภายใน read-write transaction เพื่อลดความเสี่ยงรหัสชนกันเมื่อข้อมูลเปลี่ยน
- ปรับการเปรียบเทียบกิจกรรมซ้ำให้ normalize ช่องว่าง ตัวพิมพ์ และปริมาณตัวเลข เช่น 30 กับ 30.0
- รวมราคาต่อหน่วยในการตรวจซ้ำของรายการเก็บเกี่ยว เพื่อไม่แจ้งซ้ำผิดกรณีข้อมูลมูลค่าต่างกัน
- เมื่อแก้ไขกิจกรรมแล้วพบรายการที่เหมือนกัน ระบบถามยืนยันก่อนบันทึกแทนการแสดงรหัสข้อผิดพลาด
- ปรับ Service Worker cache เป็น v6

การปรับโค้ดนี้ยังต้องทดสอบบนเบราว์เซอร์/อุปกรณ์จริงก่อนนำไปใช้กับข้อมูลสำคัญ ควรส่งออก JSON backup ก่อนอัปเดตทุกครั้ง.

## รุ่น 1.7 — เรียงลำดับรหัสรัง
- เรียงรายการรังจากรหัสน้อยไปมากด้วยการเปรียบเทียบแบบตัวเลข (เช่น B011, B012, B013, B014) โดยไม่แก้ไขรหัสหรือระเบียนใน IndexedDB
- เรียงรายการรังในช่องเลือกของกิจกรรมตรวจรัง ให้อาหาร เก็บเกี่ยว และช่องเลือกขณะแก้ไขกิจกรรมย้อนหลังด้วยหลักเกณฑ์เดียวกัน
- การเรียงเป็นการจัดลำดับเพื่อแสดงผลเท่านั้น ไม่เขียนทับข้อมูลหรือเปลี่ยน ID/ความสัมพันธ์ของกิจกรรมเดิม
- ปรับ Service Worker cache เป็น v7 เพื่อให้โหลดไฟล์แอปรุ่นใหม่


## รุ่นปรับปรุงระบบบัญชี (Accounting Upgrade)
- เพิ่มหมวดหมู่รายรับและรายจ่าย พร้อมข้อมูลฟาร์ม จุดเลี้ยง และรังผึ้ง
- เพิ่มปริมาณ หน่วย ราคาต่อหน่วย จำนวนเงินรวม วิธีรับ/จ่าย และประเภทต้นทุน
- แก้ไข/ลบรายการบัญชีได้
- สรุปรายรับ รายจ่าย กำไร/ขาดทุนสุทธิตามเดือน ปี หรือทั้งหมด และกรองตามฟาร์ม
- วิเคราะห์ค่าใช้จ่ายเฉลี่ยต่อรังและต้นทุนต่อกิโลกรัมน้ำผึ้งโดยประมาณจากกิจกรรมเก็บเกี่ยว
- กิจกรรมเก็บเกี่ยวไม่ถูกรวมเป็นรายรับอัตโนมัติ เพื่อป้องกันการนับยอดขายซ้ำ
- ปรับ Service Worker cache เป็น v8-accounting และปรับตำแหน่งไอคอนให้ตรงกับไฟล์ระดับ root ของ GitHub Pages repository
